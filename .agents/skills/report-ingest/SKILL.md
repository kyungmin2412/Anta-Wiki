# 리포트 적재

ANTA WIKI에 증권사 리포트를 넣는 두 가지 경로 중, **API 키 없이 Codex(ChatGPT) 구독으로 도는 쪽**이다.
PDF를 읽는 일은 네가 직접 하고, 검증·저장은 `npm run import`가 한다.

앱의 업로드 버튼(`/upload`)은 OpenAI API를 직접 호출하는 별도 경로다 (`AI_PROVIDER=openai`,
`OPENAI_API_KEY` 필요). 그쪽은 건드리지 않는다.

## 리포트 적재

### 1. 계약 확인

```bash
npm run contract
```

추출 지침과 JSON 스키마가 출력된다. **이 지침을 네 판단 기준으로 삼고, 스키마를 정확히 지켜라.**
스키마는 코드에서 생성되므로 항상 최신이다 — 기억에 의존해 필드를 지어내지 마라.

### 2. 컨텍스트 예산부터 정한다

**PDF는 토큰을 많이 먹고, 한 번 대화에 들어오면 이후 모든 턴에 계속 실려 간다.**
리포트 3건을 한 대화에서 처리하면 3번째 작업에도 앞의 2건이 그대로 따라다닌다.
비용이 리포트 수의 제곱으로 늘어난다.

그래서 순서가 중요하다.

**리포트가 2건 이상이면, 파일마다 서브에이전트를 하나씩 띄워라.**
서브에이전트는 자기만의 컨텍스트를 갖기 때문에 PDF 내용이 부모 대화로 넘어오지 않는다.
부모 세션은 PDF를 **직접 읽지 마라.** 각 서브에이전트에게 이렇게 시킨다:

> `reports/xxx.pdf` 한 건을 읽고, `npm run contract` 의 스키마에 맞춰 추출해
> `/tmp/ext-N.json` 에 저장하라. 저장한 뒤 파일 경로와 한 줄 요약만 보고하라.
> 추출한 JSON 내용을 응답에 다시 옮겨 적지 마라.

리포트가 1건이면 서브에이전트 없이 직접 처리해도 된다.

### 3. PDF 읽기

**필요한 페이지만 읽어라. 통째로 읽지 마라.**

국내 증권사 리포트는 필요한 정보가 몰려 있다:

1. **1페이지부터 읽는다.** 투자의견·목표주가·핵심 요약·재무 요약표가 대개 여기 다 있다.
   짧은 기업브리프라면 이것으로 끝난다.
2. 실적 추정 테이블이 1페이지에 없으면 **마지막 1~2페이지**를 본다. 상세 재무제표는 보통 뒤에 붙는다.
3. 그래도 없을 때만 중간을 훑는다.

20페이지짜리를 전부 읽으면 필요한 정보의 몇 배를 토큰으로 지불하게 된다.

읽고 나면 **같은 페이지를 다시 읽지 말고**, 추출한 내용을 응답에 길게 옮겨 적지도 마라.
JSON 파일에 쓰는 것으로 충분하다.

### 4. 추출할 때 주의할 점

- **단위 환산이 가장 자주 틀린다.** 국내 리포트 재무표는 대개 십억원 또는 조원 단위다.
  `억원`으로 맞춰라: 1조원 = 10,000억원, 1십억원 = 10억원.
  환산 후 값이 상식적인지 되짚어라 — 삼성전자 연간 영업이익이 3,000억원일 리 없다.
- **확정 실적과 추정치를 구분**하라. 표 헤더의 `2025A` / `2026F` / `2026E` 표기를 보고 `is_actual`을 정한다.
- **논조 점수는 투자의견 등급의 번역이 아니다.** 매수 의견이어도 본문에 유보 표현이 많으면 점수를 낮춰라.
- 스캔 이미지 PDF라 표를 못 읽겠으면, 지어내지 말고 그 사실을 사용자에게 말해라.

### 5. JSON 작성 후 적재

추출 결과를 임시 파일에 쓰고 적재한다. 원본 PDF를 함께 넘기면 파일이 보관되고 중복 업로드가 차단된다.

```bash
npm run import -- /tmp/extraction-1.json --pdf ./reports/samsung-mirae-20260214.pdf
```

여러 건이면 파일별로 JSON을 만들어 한 번에 넘긴다(이때 `--pdf`는 쓰지 않는다):

```bash
npm run import -- /tmp/ext-1.json /tmp/ext-2.json /tmp/ext-3.json
```

스키마 위반이면 어느 필드가 틀렸는지 경로까지 찍히고 아무것도 저장되지 않는다. 고쳐서 다시 실행하라.

### 6. 결과 보고

적재된 기업 페이지 경로(`/companies/<id>`)와 함께, `▲`로 표시된 경고를 사용자에게 그대로 전달하라.
경고는 사람이 확인해야 하는 것들이다(발간일 추정, 중복 추정치 제거 등).

## 사용량이 부담되면

Codex 경로는 추가 결제가 없는 대신 구독 사용량을 쓴다. 리포트를 정기적으로 많이 넣는다면
API 경로(`AI_PROVIDER=openai npm run ingest`)가 리포트당 대략 $0.1~0.3 수준으로 오히려
효율적이다 (정확한 금액은 리포트 길이와 추론 토큰 사용량에 따라 달라진다) — 한 건당 요청
한 번이라 누적이 없다. 사용자가 사용량 한도를 걱정하면 이 선택지를 알려줘라.

## 기업 종합 분석 생성

리포트가 2건 이상 쌓인 뒤에 의미가 있다. 1건뿐이면 "변화"가 없으므로 만들지 마라.

### 1. 계약과 입력 데이터 확인

```bash
npm run contract synthesis
```

입력으로 쓸 구조화 데이터는 DB에서 뽑는다. 기업 ID를 모르면 인자 없이 실행하면 목록이 나온다:

```bash
npm run synthesis-input                 # 기업 목록
npm run synthesis-input -- 1 > /tmp/input.json
```

### 2. 해석 후 저장

개별 리포트 요약을 나열하지 마라. **리포트 사이의 변화**를 써야 한다.
표현이 달라도 같은 논리는 하나의 테마로 묶고, 근거를 댈 때 발간일과 애널리스트를 밝혀라.

```bash
npm run import -- /tmp/synthesis.json --synthesis <기업ID>
```
